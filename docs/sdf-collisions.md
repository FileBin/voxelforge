# Коллизии по SDF (SDF↔SDF): план и договорённости

Ветка: `sdf-collision`. Заменяем тет-против-тет (`sat.comp`) на контакты между
полями расстояний.

## Что уже есть в данных

- `NodeField` в теле: значения в узлах, `step` (метров на узел), `sample()`,
  `sample_m()` (метры), `gradient()` (единичная нормаль), `expand()`,
  `intersect_plane()`.
- Поле печётся ОДИН раз на тело (`TetBody::sdf`, `OnceLock`) и переносится в мир
  (`LiveBody::sdf`), поэтому в такте его никто не пересчитывает.
- Меш строится по полю, а не по тетам; теты — разметка узлов.

## Ключевое решение: откуда стартовать

Центр AABB не годится (у тора там пусто). Старт — **узлы сетки внутри
пересечения объёмов**: узел `p`, где `f_A(p) < 0 && f_B(p) < 0`. Это
топологически нейтрально (тор, U-образные тела, зацепления работают), и данные
для этого уже лежат в вокселях.

Порядок:

1. широкий проход: AABB пары;
2. перебор узлов внутри пересечения AABB (шаг — адаптивный, чтобы уложиться в
   бюджет; кэп затравок на пару);
3. для каждой затравки 3–5 итераций спуска:
   `p -= 0.5 * (f_A(p) * n_A + f_B(p) * n_B)`, `n = gradient`;
4. контакт валиден, если `f_A(p) < 0 && f_B(p) < 0`;
   глубина `= min(-f_A, -f_B)`, нормаль `= normalize(n_A - n_B)`,
   точка `= p`;
5. дедуп: не больше N контактов на пару (8–16), распределять равномерно по
   нормалям/позициям;
6. вырожденный случай (перекрытие есть, узлов внутри нет): затравка = узел с
   минимумом `max(f_A, f_B)`.

## Шаги работ

1. **Выгрузка полей на устройство**: на тело `lo/dims/step`, поза + массив
   значений в общем буфере; проверка «данные доехали без искажений»
   (прочитать обратно несколько узлов и сверить с CPU).
2. **`shaders/sdf_contact.comp`**: перебор затравок по узлам перекрытия + спуск
   + запись контактов в тот же буфер, что у `sat.comp` (солвер не меняем).
3. **Включение в такт** под флагом (`VF_COLLIDE=sdf`), старый путь — для сверки.

## Проверка

- шар в шар с известным проникновением: глубина обязана совпасть с аналитикой
  (допуск — четверть шага узла);
- тот же сценарий, что сейчас (плита + снаряд 26 м/с): сравнить число контактов,
  максимальную глубину и скорость плиты после удара с тет-версией;
- тор против плиты: контакты должны появляться по кольцу, а не в центре;
- цена: контакты не дороже тет-пар на том же сценарии (мерить на реальной карте,
  lavapipe для этого не показатель).

## Ограничения, которые надо помнить

- Поле дискретно: точность глубины ~0.5 шага узла; для мелких осколков шаг
  крупный относительно тела — им нужен более мелкий уровень (иначе артефакты).
- Пул тетов общий на все тела (`MAX_POOL_TETS`), при переходе на SDF теты
  остаются только для меша/массы — можно будет сократить.

## Единицы поля (исправлено вместе с шагом 2)

Запечённое поле — В ШАГАХ УЗЛА, и `NodeField::step` обязан быть настоящим
шагом в метрах: `sample_m`, `intersect_plane`, `expand` и физика умножают на
него сами. Было три расхождения:

- `TetBody::cube` пёк значения в МЕТРАХ (лишнее `* step`) — глубина контакта
  по плите выходила в 14 раз меньше настоящей;
- `field::from_occupancy_metric` оставлял `step = 1.0` (параметр не
  использовался) — поле осколка оказывалось в 14 раз крупнее осколка;
- `intersect_plane` и `expand` считали в метрах.

Теперь все пути согласованы; срез поля осколков для коробки-родителя не
изменился (решение о знаке на узле то же), для родителя с полем по занятости
срез стал точным.

## Ограничения (что осталось)

- Точность глубины ~полшага узла. У плиты (куб, аналитическое поле
  повёрнутой коробки) ноль поля лежит на ~2 шага выше оболочки тетов, а
  широкий проход берёт AABB по ТЕТАМ — значит SDF-контакты появляются, когда
  теты уже пересеклись, и глубина считается по полю, а не по тетам. Для сверки
  с SAT это надо помнить: у плиты две разные «поверхности».
- Затравки идут по узлам тела с меньшим полем, кусками по 64 потока, не
  больше 2 контактов с потока. Глубоко утопленное тело даёт до 128 контактов
  на пару, дальше режет `contact_select` (24).
- Спекулятивной маржи (как в `sat.comp`) у SDF-прохода нет: контакт появляется
  только при реальном перекрытии полей. На 26 м/с при 8 подшагах этого
  хватает (проверено), на 120 м/с нужен прогон и, возможно, маржа по полю.
- Цена на lavapipe: см. `probe_sdf_collide` (строка «такт»); на живой карте не
  мерили.


## Туннелирование быстрых тел: CCD по SDF и габаритам (сделано)

Симптом: тело на большой скорости проходило сквозь другое, на малой —
сталкивалось нормально. Причина не в солвере, а в обнаружении: контакт искался
только в позах на концах шага, а за шаг самое быстрое тело смещалось дальше
собственного размера (240 м/с · 50 мс = 12 м при плите 1.12 м и шаре 0.28 м).

`crates/world/src/ccd.rs` + `Live::ccd_pass` (вызывается в `step_gpu` ПЕРЕД
отправкой такта, работает для обоих путей контактов):

1. **Порог** — только относительное смещение за шаг больше размера меньшего
   тела (`needs_continuous`, размер = габарит ПОЛЯ, не радиус тетов: у шара
   r=0.14 теты дают 0.2 и порог срабатывал раньше времени). Медленные тела идут
   прежним путём. Пробные точки строятся ПОСЛЕ порога и кэшируются по `id`
   тела: сборка — обход сетки поля, и раньше она случалась в кадре раскола для
   десятков новых тел сразу.
2. **Пробные точки** — 64 штуки: узлы поля у поверхности (глубина `d` под
   собственной поверхностью), ЦЕНТР габарита с глубиной вписанного радиуса и
   шесть точек по осям габарита, когда узлов внутри меньше 32. Касание —
   `f_другого(p) < d`. Центр нужен для случая «партнёр целиком внутри
   пробного»: у мелкого осколка все узлы в одном слое, поверхностные точки
   партнёра не касаются, и шар проходил сквозь. Обход сетки прорежен до 8192
   узлов (`PROBE_SCAN_NODES`), глубина берётся из первых слоёв (`|v| ≤ 2`).
3. **Интервал** — аналитически: отрезок движения ЦЕНТРА пробного тела против
   ОСЕВОЙ КОРОБКИ партнёра, раздутой на габаритный радиус пробного
   (`seg_box`/`sweep_sphere_box`). Раньше здесь был сферный трейсинг по полю с
   шагом `|f|` и равномерный проход из 48 проб: вне блока поля `|f|` зажато к
   значению на границе, трейсинг топтался на месте, а 48 проб по 12 м пути —
   это шаг 25 см. Мелкий осколок в 3 см такой шаг пролетал целиком.
4. **Поиск** — внутри интервала 16 проб ищут первую долю шага с `f - d < 0`,
   дальше бисекция до 1e-3 перемещения (12 итераций — потолок). Вне блока поля
   расстояние считается до САМОГО БЛОКА (`BodyView::surf`): зажатая выборка
   давала «+0.009 м до поверхности» в трёх метрах от осколка, и центр шара
   (глубина 0.13) считался «уже в контакте» — CCD молча выключался.
5. **Тонкое поле** — если занятая область поля тоньше трёх узлов, поле
   геометрию не описывает (у скола остаётся слой), и контакт считается
   аналитически по габаритной коробке (она же коллайдер GPU). Промахнуться
   нечем.
6. **Нормаль и точка** — точка касания: центр пробного тела, спроецированный
   на поверхность партнёра (проекция по полю; вне блока — clamp в габарит).
   Нормаль — градиент поля В ТОЧКЕ КАСАНИЯ; если он вырожден или даёт меньшее
   сближение, чем грань габарита, берётся грань. Раньше нормаль брали в
   «глубочайшей» пробной точке: у мелкого осколка это внутренняя точка, где
   ближайшая грань совсем не та — удар двух осколков бок о бок получал нормаль
   ВВЕРХ (Δv цели 0.06 м/с вместо 60), а шар в плиту крутился до 200 рад/с.
7. **Плоскости** — пол (`y=0`) и стены мира идут отдельным проходом ДО пар:
   отрезок опорной вершины габарита против плоскости за шаг, затем тот же
   импульс, что у контакта, и БУДИЛЬНИК спящего. CCD плоскостей раньше не
   покрывал вовсе.
8. **Применение** — тело ставится в позу касания, нормальная скорость гасится
   импульсом `solve.comp`. Из пары «плоскость» и «партнёр» применяется РАННИЙ
   удар: пока плоскость применялась до пар, снаряд у стены гасился о стену в
   конце того же такта, так и не проверив осколок (240 м/с, путь 12 м).
   Энергия удара уходит в очередь раскола (`ccd_impacts`): без контакта в
   списке событие с устройства не пришло бы, и плита перестала бы колоться.

Числа. Плита дробится три поколения (`probe_ccd_small`), затем снаряд летит в

## SDF-контакты — путь по умолчанию (найдено и исправлено)

Симптом пользователя: «тела проходят друг сквозь друга, удара нет вовсе».
Числами: шар 20 м/с в лежащий шар — пар тел 3, контактов **0**, цель не
шевельнулась (Δv 0.00), снаряд пролетел. Причина — не «мягкость», а три
структурные ошибки узкой фазы и одна в широкой. Все найдены на числах, не на
глаз (`probe_hardness`, `probe_sdf_dump`, `probe_sdf_sink`, `probe_sdf_balls`).

1. **Затравки требовали «узел внутри ОБОИХ полей»** (`fs < 0 && ft < 0`). У шара
   r=0.14 внутри ровно один узел (центр); он попадал внутрь партнёра только при
   перекрытии на радиус. На 20 м/с (0.125 м за подшаг) это окно проскакивало за
   один подшаг. Теперь затравка — по ЗАЗОРУ: `fs + ft < marg`, где сумма
   знаковых расстояний есть зазор в точке (минус внутри), а
   `marg = 3 шага узла + относительный путь за подшаг`. Глубина стала знаковой:
   `-(va+vb)`, отрицательная — спекулятивный контакт.
2. **Солвер игнорировал `pen<0`**: `push = max(pen - margin, 0)*beta/dt` даёт 0,
   а `dl = max(push - vn, 0)` гасил ВСЮ скорость сближения — тело замирало в
   воздухе на величину маржи. Добавлена ветка `push = pen/dt` (сближаться ровно
   на зазор) в `solve_contacts.comp`. Правило общее с SAT: sat.comp.margin тоже
   отдаёт `pen<0`.
3. **AABB широкой фазы считался по ТЕТАМ**, а ноль поля лежит на ~3.5 см ВЫШЕ
   оболочки тетов у плиты. Пара «шар касается плиты по полю» в список пар не
   попадала вовсе (перекрытия тетов нет). Теперь `body_aabb.comp` объединяет
   габарит тетов с ГАБАРИТОМ ПОЛЯ (8 углов сетки).
4. **Нормаль разворачивалась не в ту сторону** при затравке из второго тела
   (`ga-gb` считалась ОТ ЗАТРАВКИ): у пары «плита + шар» нормаль выходила
   наружу, `vn > 0`, `dl = 0` — контакты в списке есть, солвер молчит.
   Теперь нормаль приводится к «от ia к ib» (флаг `a_seed`).
5. **Одна нормаль на пару** (нормаль самого глубокого контакта). До этого шар,
   утопленный в плиту, получал два десятка точек «шапки» с наклонными
   нормалями: момент не сокращался, спин −11.8 рад/с от вертикального удара,
   дальше нормализация кватерниона и NaN. SAT по той же причине берёт одну ось.
6. **Единицы**: `fs + ft` складывались в УЗЛОВЫХ единицах двух разных сеток
   (плита 0.035, шар 0.00875) — теперь оба множатся на свой шаг.
7. **Глубина = max(узел, спуск)**: спуск ищет пару ближайших точек поверхностей,
   у двух выпуклых тел это окружность пересечения (сумма 0), а не глубина
   перекрытия (у двух шаров с перекрытием 0.1 м спуск давал 0.002). Берём
   большую из двух.
8. **Цена**: быстрый выход на глубоком перекрытии (узел глубиной в шаг сетки —
   достаточно). `sdf_contact` на lavapipe: было 200 мс/такт (80 % такта), стало
   в среднем 27 мс (макс 69).

- **Глубина на плоских/гранёных телах врёт**: куб на плите при заглублении
  0.09 м даёт глубину 0.21 м на GPU и ~0.00 м на CPU-оракуле — знак и величина
  нестабильны у параллельных граней (узкая фаза берёт «самый глубокий узел», а

  «вязнет» и останавливается позже, чем на тет-пути.

  спин 2.5–3 рад/с у шара после удара (трение/угловое гашение его съедают
