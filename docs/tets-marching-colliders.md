# Сетка тетов, марчинг и коллайдеры из SDF — план

## 1. Замощающий тет: Sommerville #1

Нужен тет, которым ПРОСТРАНСТВО ЗАМОЩАЕТСЯ без искажений и без «Y-сшивки».
Такой тет — прямой ортосхем: **1/6 куба**. Куб режется на 6 конгруэнтных
тетов по главной диагонали; шесть тетов складываются обратно в куб, кубы — в
пространство. Рёбра внутри куба: три взаимно перпендикулярных ребра длины a у
общего угла, три «диагональных» (a√2, a√2, a√3). Никакой подгонки вершин, все
грани совпадают грань-в-грань с соседними кубами — сетка из одних и тех же
тетов, просто со сдвигом.

Практическая раскладка: глобальные координаты тета задаются (клетка, номер
тетa 0..5), где номер — одна из 6 перестановок осей куба. Это чистая
арифметика без хешей и без поиска соседей.

Что это даёт:
- единая форма тета во всей сетке → массивы (cell, tet) без «каких-то»
  тетов разной формы;
- грани соседей совпадают точно (одинаковые вершины в целых координатах) —
  значит марчинг не даёт щелей между клетками;
- деформация и разрушение — это не геометрия, а состояние: набор занятых
  тетов + поле плотности.

## 2. Marching tetrahedra (сейчас его нет)

Сейчас из тетов просто берутся вершины и соединяются — поверхность выходит
гранёной и рваной. Нужен настоящий marching tetrahedra:

1. по каждому тету считать знак поля в 4 вершинах (SDF или воксельная
   плотность);
2. по 16 комбинациям знаков — 0, 1 или 2 треугольника, точки пересечения по
   рёбрам с линейной интерполяцией;
3. вершины на рёбрах кэшировать по ключу ребра `(cell, tet, edge)` — иначе
   соседние теты дадут дубли вершин и швы (это и есть «Y-сшивка», которой быть
   не должно);
4. индексы в общий буфер, нормали — градиент поля (центральные разности по
   сетке), не по треугольнику.

Порядок работ: сначала CPU-эталон марчинга (проверка на сфере по SDF — площадь
и отсутствие дыр), потом перенос на GPU по образцу `voxel.comp`/`mesh.comp`.

## 3. Коллайдеры из воксельного поля / SDF

Да, считать коллайдеры из SDF можно, и это правильнее, чем выводить их из
тетов. Три варианта, по возрастанию точности:

| подход | что даёт | цена |
|---|---|---|
| **набор сфер по полю** (point/capsule set) | коллайдер совпадает с полем по построению; идеально для GPU (SAT по сферам дешёвый) | много «примитивов» на тело, но их число можно ограничить жадным покрытием |
| **выпуклая декомпозиция изоповерхности** (V-HACD по марчинг-мешу) | точная форма, привычный SAT по коробкам | офлайн-шаг на спавне, дорого |
| **sphere tracing по SDF** | точная, без прокси | на каждый контакт — марш по полю, для такта 20 Гц дорого |

Рекомендация: **сферы/капсулы, запечённые из поля** (жадное покрытие
вокселей сферой максимального радиуса, ограничение N=32..64 на тело), плюс
запасной вариант «коробки из декомпозиции» для крупных цельных объектов.
Прокси-сферы уже используются сейчас (октаэдр, вписанный в сферу), так что
переход не ломает солвер.

## 4. Что это меняет в текущем коде

- `tet.rs` (пул тетов, `TetBody`, `local_tets`, `rotated_tets`) — заменяется на
  сетку из ортосхемов: позиция тета = (клетка, номер перестановки).
- `shaders/tet_key.comp`, `tet_fill.comp` — ключ ячейки теперь может быть
  детерминированным (номер клетки = int-координаты), сортировка не нужна:
  диапазон записей клетки считается арифметически.
- `mesh.comp` — заменяется marching tetrahedra по полю.
- `collide`/`sat.comp` — вход не «пары тетов», а пары выпуклых прокси
  (сферы/капсулы), запечённых из поля.

## 5. Открытый вопрос

«Без Y-сшивки» — имеется в виду именно отказ от сшивания вершин на рёбрах
(кэш вершин по ключу ребра) или что-то другое (например, отказ от Y-образных
узлов сетки)? От этого зависит структура марчинг-пасса.
