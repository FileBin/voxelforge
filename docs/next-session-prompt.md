Скопировать целиком в новую сессию.

Проект `~/projects/voxelforge` — GPU-резидентный воксельный движок на BCC
(C-ядро Vulkan + Rust-хост). Ветка **`device-merge`** (уже создана и запушена,
HEAD `3ee47ae`), от `gpu-collide`.

## Задача

Выполнить план из `docs/plan-sync.md` по шагам, начиная с шага 0. Цель — убрать
последнюю синхронизацию с CPU в живом режиме:

- шаг 0: **один общий Vulkan-девайс** у ядра физики и окна (сейчас их два:
  `c/voxelforge_core.c` создаёт свой instance+device, `c/voxelforge_view.c` свой);
- шаг 1: `read_bodies` → рендер читает позу из буфера тел (SSBO, номер тела
  push-константой, интерполяция в шейдере); `LiveBody` теряет позу и скорость;
- шаг 2: `read_impact` → кольцо событий раскола + счётчик 4 Б, читать только
  при изменении;
- шаг 3 (по желанию): `write_bodies` → спавн/деспавн через очередь команд.

Шаг 4 (мешер на GPU) решили НЕ делать — см. план.

## Обязательное перед началом

1. Прочитать `docs/plan-sync.md` и `docs/handoff.md`.
2. `git log --oneline -15` — что уже сделано; ничего из перечисленного не
   переделывать.
3. Убедиться, что дерево собирается: `nix develop --command bash -c 'cargo build --release --features live'`.

## Как проверять

- Сборка: `nix build .#live -o result-live`
- Окно headless (sway + lavapipe):
  `nix develop .#headless --command bash -c 'VF_COLLIDE=gpu VF_PAIRS=gpu scripts/headless-run.sh ./result-live/bin/voxelforge-live 200 20,60,120'`
  В логе должна быть строка `[live] конец: кадров ... тел ... трещин ... осколков`.
- Туннелирование: `cargo run -q --release -p voxelforge-refsim --example probe_fastshot`
  (должно давать трещины на всех скоростях 26/60/120/240).
- Время такта: `... --example probe_time`.
- Полный набор: `cargo test --locked` и `nix flake check`.

## Правила работы (важные)

- **Мелкие коммиты**, после каждого — собирается и проходит headless. Откат =
  удалить последний коммит.
- Шаг 1 **меняет картинку** (сглаживание движения считается на GPU) — отдельный
  коммит, чтобы откатывался одной командой, и предупредить меня, когда смотреть
  глазами.
- **Не трогать трение** в `shaders/solve.comp`. Не «успокаивать» тела сменой
  коллайдеров.
- Позиции тел не должны покидать GPU по-хорошему; отладочное чтение — только по
  флагу (`VF_DEBUG=1`).
- Реальный GPU есть только у меня; в среде агента — lavapipe. Всё, что меняет
  картинку, проверяю я в окне.
- Не останавливаться, пока шаг не проверен; если шаг нельзя закончить безопасно
  — откатить и сказать прямо, а не оставлять полудоделанное дерево.

## Состояние на момент передачи (кратко)

- Пары тетов считаются на устройстве (`VF_PAIRS=gpu`): `body_aabb` → `tet_key` →
  `tet_scan` → `tet_fill` → `tet_pairs`, одним submit'ом.
- Энергия удара считается на устройстве до солвера (`impact.comp`) — быстрый
  снаряд ломает плиту, туннелирования нет (проверено на 26/60/120/240 м/с).
- Сетка тетов: клетка 0.16, потолок пар 65536, потолок записей 262144.
- Из такта остались два чтения: `read_bodies` (7 КБ, для рендера) и
  `read_impact` (2 КБ, для раскола) — снимает этот план.
- Шаги 0–3 не начаты; ветка `device-merge` = состояние `gpu-collide`.
